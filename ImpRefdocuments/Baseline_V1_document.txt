# AI Infrastructure Sizing Engine

## V1 Technical Specification

**Status:** Engineering Baseline
**Version:** 1.0
**Target:** Local Windows 11 development → production deployment
**Architecture:** Modular Monolith
**Primary Deployment Modes:** On-Premises, Cloud, Hybrid

---

# 1. Purpose

The AI Infrastructure Sizing Engine is a deterministic, catalog-driven application that converts business, workload, AI-model and infrastructure requirements into:

* AI workload estimates
* model recommendations
* GPU/CPU/RAM/storage/network requirements
* physical infrastructure topology
* HA/DR capacity
* growth capacity
* infrastructure BOM
* pricing
* CAPEX/OPEX
* 3-year and 5-year TCO
* On-Prem / Cloud / Hybrid comparisons
* calculation lineage
* evidence and confidence
* PDF, Excel and JSON reports

The system is designed for **engineering decision support and infrastructure planning**, not merely dashboard visualization.

---


# 5. Architectural Principles

## 5.1 Deterministic calculation

For identical:

* input version
* model catalog version
* hardware catalog version
* benchmark version
* assumption version
* pricing version
* calculation-engine version

the engine must produce the same result.

---

## 5.2 Catalog-driven

Technical values must not be hard-coded into calculation logic when they belong in a catalog.

Examples:

```text
GPU memory
GPU TDP
server GPU count
server CPU count
server RAM
server networking
cloud hourly price
model parameter count
model context window
benchmark throughput
utilization target
growth rate
complexity multiplier
```

These belong in governed data.

# 31. Authentication and Authorization

V1 uses local authentication.

## USER

Can:

```text
login
create project
edit own project
run sizing
view results
generate reports
export reports
```

Cannot:

```text
edit catalogs
edit benchmarks
edit pricing
edit assumptions
edit evidence
manage users
```

## ADMIN

Can perform everything a USER can, plus:

```text
create/update/archive catalogs
create/update evidence
manage benchmarks
manage pricing
manage assumptions
manage models
manage hardware
manage cloud configurations
manage users
```

# 36. Effective User Calculation

For every use case:

```text
If Approx Users exists:

    Effective Users = Approx Users

Else:

    Effective Users =
        Total Users × Applicable Users %
```

The system retains both:

```text
percentage-derived users
user-supplied approximate users
```

If they materially differ:

```text
WARNING: USER_OVERRIDE_DEVIATION
```

# 37. Daily Transaction Contract

```text

=
```


# 38. Peak Concurrency Distribution

Do NOT distribute concurrent sessions evenly.

```text
DistributionWeight[u]
=
EffectiveUsers[u]
× UsageIntensityFactor[u]
```

Then:

```text
PeakConcurrentRequests[u]
=
PeakConcurrentSessions
× DistributionWeight[u]
/
Σ DistributionWeight
```

The intensity factor comes from the assumption/use-case catalog.

```text
=
```

```text
calculation execution
report generation
```

# 85. Important Engineering Rule

The LLM is **not** the authoritative sizing calculator.

If an LLM is added later, its role can be:

```text
Explain
Summarize
Answer questions about results
Generate narrative
Highlight assumptions
```

It must not independently decide:

```text
GPU quantity
server quantity
BOM quantity
TCO
```

Those come from the deterministic engine.

```text
        ┌──────────────────┼──────────────────┐
        │                  │                  │
        ▼                  ▼                  ▼
     Identity          Projects           Catalogs
        │                  │                  │
        └──────────────────┼──────────────────┘
                           ▼
                  ┌─────────────────┐
                  │ SIZING ENGINE   │
                  ├─────────────────┤
                  │ Validation      │
                  │ Workload        │
```

That dependency chain is the backbone of the entire product.
